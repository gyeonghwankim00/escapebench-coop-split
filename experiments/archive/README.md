# 설계 변경 아카이브

과거 문서의 "현재", "권장", "아직 미검증"은 작성 당시의 표현입니다.
실행은 [현재 서버 안내](../../server/README.md), 연구 해석은
[현재 설계](../CURRENT_DESIGN_AND_DATASET_REVIEW.md)를 기준으로 합니다.

## 방향이 바뀐 이유

| 단계 | 설계 / 변경 근거 | 현재 해석 |
|---|---|---|
| 초기 JSON 파일럿 | 3문제 축약 후 원본 과정을 보존한 8문제로 확장; 브라우저 체험 | `data/pilot`과 앱에 유지. 현재 12문제 역할 분할과 별개 |
| 작은 모델 Solo | Qwen8B에서 실행·프롬프트·thinking·힌트 진단 | 다른 생성/기억/환경 조건이므로 현재 성능과 합산 불가 |
| 원본 기반 실행 | 원본 Graph/BaseAgent와 14B·32B 비교, greedy 설정 검증 | 모델 호출·원본 보존 기반; 별도 original_solo 경로 유지 |
| 초기 Solo/Peer | Solo는 분할 전 원본, Peer만 분할 환경 | 시작 위치·관측 기회 차이가 협력 효과와 섞임 |
| 같은 분할 Solo | 양쪽 위치 관측 후 불필요한 요청 제거, 공용 가방 도입(v3–v5) | 중앙 통제와 무료 공유를 비교 기준으로 정립 |
| 비용·탐색 개선 | 자유로운 Solo 역할 선택, Peer 4판단 상한·양도, 관측 기억(v6) | 교대 유휴·잘못된 명령 파싱·기억 소실의 교란을 줄임 |
| 현재 v7 | 역할별 동일 기억, Solo 3줄/Peer 2줄, 독립 분류, 발견 기록, 무힌트 500행동 | `nightly-v6`; 핵심/확장/대조/제외를 구분하는 새 진단 실험 |

v7의 후속 발견 기록 수정은 첫 실험 전 변경이라는 전제에서 이름을 유지했습니다.
실제로 예전 코드로 생성한 v7 폴더가 있으면 해시 불일치로 재개가 거부됩니다.
이때 기존 결과를 덮어쓰지 말고 보존 후 별도의 새 경로로 실행해야 합니다.
