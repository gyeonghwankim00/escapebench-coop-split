회의에서 결정할 네 가지

01 · 어떤 협력을 평가할까?

정보 전달·해석·활용에 집중할지, 도구 전달과 탐색·역할 분담까지 포함할지. 현재 Solo/Peer 차이는 이 비용들이 합쳐진 결과다.

02 · 어떤 문제를 본 실험에 넣을까?

핵심 6개를 출발점으로 사람이 경로를 검증. 초기 유휴·후반 통신 병목·분할에 의한 지름길을 확인하고 확장·대조군은 분리 보고.

03 · 입력·행동 규칙을 어디까지 통제할까?

현재 텍스트 명령을 유지할지, 구조화된 행동 선택을 쓸지. 기억·역할 선택·메시지 비용과 무힌트 주 평가를 실험 전에 고정.

04 · 어떤 모델에 예산을 쓸까?

오픈 모델로 저비용 반복 검증 + 소수 고정 문제에 GPT/Claude API 비교를 제안. 모델·호출 비용 상한·반복 횟수를 함께 결정.

다음 실행 제안: 조건을 바꾸지 않고 OOM 2개 보충 → 대표 문제의 사람 검증 → 합의한 프로토콜을 새 버전으로 고정 → 강한 모델 소규모 비교. 실패 사례마다 규칙을 덧붙이는 방식은 피한다.

평가용 로그tracking, evaluation, 진행률, 정답 관련 평가 정보는 아래 감사용 원본 JSON에만 함께 저장된다. 모델 입력은 generation.messages이며, 로그 전체가 프롬프트로 전달되는 것은 아니다.
