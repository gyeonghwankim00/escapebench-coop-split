# 방 분할 v4 — 전체 easy 데이터와 관측 근거 검증

2026-11-25 분할 정비본. **원본 12문제를 모두 수록하고, 사용 가능 11개와 제외 1개를 구분한다.**
이 폴더가 새 분할의 기준이다. 기존 `data/roles/`와 `coop_split/`은 과거 v3 재현용으로 유지한다.
실험 실행기·모델·프롬프트·스케줄링 설정은 변경하지 않았다. 일반 실험 실행기는 아직 v3를 읽는다.

양쪽을 반드시 50:50으로 만들거나, 모든 게임에 독립 초기 퍼즐을 새로 추가하지 않았다.

## 수정 범위와 원본 보존

- 분할로 쓸모없어진 입장 퍼즐만 삭제한다(1-2, 1-3, 2-2).
- 연결을 옮길 때 문 물건도 함께 옮기고, 남는 물건의 상태·트리거·정답은 바꾸지 않는다.
- 1-5의 빈 왼쪽 방 삭제는 정답 행동을 삭제하지 않는다.
- **2-3만 원본 이동 결함을 보정한다.** default/hard에 이미 있는 선반 진입 연결을 easy에도 넣는다. 난이도 설명이나 단서를 default/hard로 교체하지 않는다.
- 나머지 게임 YAML은 원본의 바이트 그대로 복사한다. 원본 `vendor/escapebench`는 수정하지 않는다.
- 삭제한 29개 정답 단계와 이동·설명 수정의 전후, 원본 해시는 `edits.json`에 남긴다.
- 따라서 “원본 모든 논리 과정 보존”이라고 부르지 않는다. **필수 퍼즐을 유지하고 분할로 무의미해진 입장 과정을 제거한 재구성**이다.
- 원본 단일 플레이와 분할 Solo는 다르다. 이 자료의 Solo는 같은 v4 A/B 위치를 한 사람이 통제하고 가방을 공유하는 조건이다.

## 정답을 알고 있다는 이유만으로 PASS하지 않는다

`split_evidence.py`는 평가자 전용 장부다. 실제로 보였던 장면·물건·가방 설명과 행동 결과만 관측 근거로 등록한다.
단서 주석은 무엇을 확인할지 정할 뿐, 주석의 정답이나 숨겨진 YAML 상태를 관측으로 간주하지 않는다.

1. 모든 `input`에 단서 주석이 있어야 한다. 누락은 실패다.
2. 해당 단서의 실제 내용이 플레이어에게 보인 적 있어야 한다. 닫힌 서랍을 봤다는 것만으로 그 안의 숫자를 안다고 하지 않는다.
3. Peer에서 다른 역할이 본 정보는 실제 `send`의 성공 응답 이후에만 수신자가 안다고 처리한다. 물건 자체를 받은 경우에는 자기 가방에서 읽을 수 있다.
4. 메시지는 관측한 원문 전체를 사용한다. 긴 단서는 280자 단위로 나눠 실제 여러 번 전송한다. 표·괄호·여러 줄 내용도 보존한다.
5. 암호 입력 직전 수신자의 프롬프트에 그 근거 또는 전달된 메시지 조각들이 있어야 한다.
6. 근거가 부족하면 원래 정답 파일에 답이 있어도 재생은 실패한다. 전달하지 못한 출처나 정답 단계 생략을 허용하지 않는다.

2-2의 정상 경로 예:

```text
B: apply(entrance guard card, drawer)
B observes: The drawer is opened, and there is a paper with a number "1040"
B: send(The drawer is opened, and there is a paper with a number "1040")
A receives the message.
A: input(1040, wall safe)
```

각 입력의 출처·관측 역할·관측 시점·전송 시점은 `verification.json`의 `input_evidence`와 `transmissions`에 남는다.
이동·수집·조합·물건 전달은 원본 엔진이 수행한다. 임의 순간이동, 무료 물건 이동, 힌트나 강제 정답 입력은 실제 정답 재생에 사용하지 않는다.

**검증용 기억:** 분할 자체를 검사하기 위해 관측 노트북을 충분히 크게 잡았다. 정답을 아는 계획자가 행동 순서를 고르지만, 그 순서에서 필요한 정보의 확보를 별도로 검사한다.
이는 유한 기억 모델의 성능 검사가 아니며, 기존 실험의 기억 설정은 바뀌지 않았다. 정답 경로는 최단 경로도 아니다.

## 구조 검사와 한계

- **관측 기반 도달 검사:** `full`, `no_messages`, `no_give`, `only_A`, `only_B`를 모두 기록한다. 자유 탐색과 올바른 해석을 가정한 상한이며 모델 성공률이 아니다.
- 기존 `alone_A/B`는 암호를 이미 아는 상한이다. 현실적인 초기 독립 진척은 `quality.initial_independent_observed`를 사용한다. 임의의 10% 기준을 숨겨서 통과시키지 않는다.
- **불필요 단계 검사:** 원본과 v4에서 정답 행동을 하나씩 빼고, 관측 근거를 요구하며 차이를 확인한다. 모든 대안 행동 순서를 탐색한 최소성 증명은 아니다.
- 2-4는 답을 미리 안다고 치면 19단계를 생략할 수 있지만, 단서를 관측해야 하면 생략할 수 없다. `known_codes`는 진단용이고 `observed_clues`가 통과 기준이다.
- **원격 효과:** 보존한 모든 교차 트리거를 `remote_effects`로 공개한다. 자동 알림을 추가하거나 엔진 잠금을 바꾸지 않았다. 상대 역할이 다시 관측하거나 메시지를 보내야 변화에 대응할 수 있다.
- 1-4는 관측 기반 전체 진행도 탈출하지 못하는 제외 사례로 검사한다. 검증 보고서의 전체 PASS는 이 제외를 올바르게 판정했다는 의미를 포함한다.
- 테스트와 재생은 실행 가능성과 주석으로 정의한 정보 경로를 검증한다. 모든 자연어 해석·모든 가능한 행동 순서의 완전성을 보장하지 않는다.

## 파일과 사용

| 파일 | 의미 |
|---|---|
| `games/`, `roles/`, `reference/` | 12개 게임의 환경·구역 배정·원본 행동 정답 경로 |
| `clues.json` | 전체 단서 주석. 평가자 전용 |
| `cohort_policy.json` | 전체 분류. 공간·초기 의존성의 세부 판단은 이 문서와 검증 결과 참조 |
| `edits.json` | 변경 근거, 삭제와 이동 목록, 원본 해시 |
| `replays/*.solo.json`, `*.peer.json` | 사용 가능 11개 × 두 조건의 실제 실행 경로 |
| `verification.json` | 결과, 예외·제외, 모든 데이터 해시, 입력별 관측·전달 증거, 구조 검사 |
| `artifact_games.json` | 사용 가능 11개를 보여주기 위한 데이터. 기존 외부 아티팩트에 자동 반영되지는 않음 |

```bash
python3 -m scripts.split_v4 build
python3 -m scripts.split_v4 verify
python3 -m unittest tests.test_split_v4
```

PyYAML과 requests가 설치된 Python 환경에서 실행한다. CPU만 사용한다.
`build`는 기존 PASS를 무효화하고, `verify`도 시작 시 미완료 상태로 바꾼다. 검증이 끝나기 전에 오래된 PASS를 재사용하지 않는다.
